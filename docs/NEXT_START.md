# 세계 예측기 — 다음 작업 시작 가이드

최종 갱신: 2026-11-27

## 한 줄 요약
인공지능프로그래밍실습 과제용 Windows 단독 실행 게임. 멸망한 시뮬레이션 세계를 탐험하며 단서를 모으고, 현실로 돌아와 보고서로 추론하는 횡스크롤 게임. 8시간 안에 완성이 목표.

## 현재 상태
- 완료
  - 이동·점프·카메라, 바닥 재질별(wet/mud) 이동 보정
  - 메뉴식 확률 전투, 징후 문장, 적 데이터 `data/enemies.json`, 맵 접촉 시작 (텍스트 UI 플레이스홀더)
  - 전투 확장: 매 턴 선택지 3개가 랜덤으로 바뀜(공격·방어·회피·강타·치료), 자원 "집중"(행동별 비용), 5초 원형 타이머, 시간 종료 시 화면의 선택지 중 랜덤 자동 선택. 스토리용 고정 선택지는 적 데이터 `options.fixed`로 지정
  - 조사 지점(E)과 단서 수첩(Q), 세계 1 단서 16개 `data/clues.json`, 장면 재시작 후에도 단서 유지
  - 단서 분석(수첩 안): 믿음/보류/의심 표시(Z/X/C), 단서 연결 모순/뒷받침(V), 추론 카드 만들기(R: 단서 2~3개 + 결론 후보 선택), 카드 목록(Tab, 삭제 Del). 결론 후보는 `data/inferences.json`(참 5개, 거짓 3개). 수첩은 정답 여부를 알려 주지 않으며, `ClueBook.evaluate_card()`가 보고서 단계에서 쓸 평가("valid"/"unsupported"/"wrong")를 이미 제공함
  - 보고서 시스템: 귀환 장치(맵 끝, E) 또는 전투 패배 시 보고 화면 → 원인 선택 → 근거 카드 첨부 → 등급·한 줄 코멘트·힌트 → 보급품 선택 → 새 시뮬레이션. B 이상이면 다음 세계 해금 안내(세계 2·3은 아직 없음). 점수 계산은 `scripts/report_logic.gd`, 설정은 `data/report.json`. 설계는 `design/03_보고서_설계.md`
  - 이동 장치 4종(사다리 W/S, 크랭크 승강기 E, 스파크 구간, 전력 레버·전자문)과 맵 상태 규칙(전력 레버는 매 판 초기화, 지름길은 영구). 시험장: `godot --path game scenes/gym.tscn` (R로 새 판). 맵 제작 도구는 `scripts/level_kit.gd`. 설계는 `design/04_세계1_레벨_설계.md`
  - **연속 맵 조립**: 글자 격자 구역 파일(`data/world1/*.txt` + `world.json`)을 읽어 하나의 큰 맵으로 만든다(`world_data.gd`, `world_builder.gd`, 장면 `scenes/world1.tscn`). 지금은 거리 + 병원 두 구역. 도달 가능성 자동 검사(`world_nav.gd`). 승강기는 정류장에서 E로 부를 수 있음. 실행: `godot --path game scenes/world1.tscn`
- 임시 처리 (스토리 확정 후 바꿀 것)
  - 단서와 전투 징후의 연결: 지금은 F1 키로 징후 단계(0/1)를 수동 전환. 연결 규칙은 사용자가 나중에 확정하기로 함.
  - 처치 보상, 전투 후 맵의 적 처리: 이기면 적이 사라지고, 지면 시뮬레이션 재시작
  - 조사 지점 16개를 테스트 맵에 일렬로 배치(실제 구역 배치는 레벨 단계에서)
  - 단서의 시점(사건 전/중/후)은 설계 문서에 명시가 없어 제가 임의로 지정함. 확인 필요.
- 임시 처리 추가: 추론 결론 후보는 세계 1용만 있음. 믿음/의심 표시·연결·카드는 저장되지 않음(게임을 끄면 사라짐).
- 미착수: 대화/선택(싸움·대화·회피), 보고서, 현실 거점(3D), 세계 1 실제 레벨, 세계 2·3, 그래픽, 사운드, 빌드

## 외부 라이브러리 (도입한 것)
- **Dialogue Manager v4.2.0** (nathanhoad, MIT, Godot 4.6+). `addons/dialogue_manager/`에 원본 그대로 넣었고 라이선스 원문도 같은 폴더에 있다. 대화 파일(`.dialogue`)에서 우리 게임 함수를 조건(`[if has_clue("s1_f") /]`)과 동작(`$> give_clue("s1_c")`)으로 호출할 수 있다. 사용법과 우리 상태와의 연결 예는 `tests/test_dialogue_addon.gd` 참고.
  - 검토 결과: 런타임 코드에 네트워크·외부 실행 호출 없음. 에디터 전용 코드(`components/`, `views/`)만 GitHub 업데이트 확인(HTTP)과 `OS.shell_open`을 쓰며 내보낼 때 제외된다. 에디터를 열 때 업데이트를 확인하므로 `user://dialogue_manager_user_config.json`에 `check_for_updates=false`를 넣어 두었다(이 파일은 저장소에 없고 PC마다 다름). 조건·동작 평가에 `Expression`을 쓰므로 **신뢰할 수 없는 대화 파일은 불러오지 않는다**(우리가 쓴 파일만 사용).
  - 업데이트는 직접 하지 않는다. 새 버전이 필요하면 별도 폴더에 받아 같은 방식으로 검토한다.
- 검토용 복사본은 저장소 밖 `..\_external_review\`에 있다(지워도 됨).
- 사다리·스파크·레버·승강기를 주는 외부 애드온은 마땅한 것이 없어 직접 구현했다.

## 확정된 결정
- 조작: A/D 이동, Space 점프, W/S 사다리, E 조사·조작, Q 수첩, 전투는 1/2/3 또는 마우스(5초 안에 선택)
- 해상도: 480x270을 임시 사용. 최종 도트 크기는 그래픽 단계에서 확정.
- 이동·점프 수치는 현재 값 유지. 환경별(비, 진흙 등)로는 다르게 한다.
- 전투: 실시간 아님. 메뉴식 확률 전투, 징후는 문장으로만, 단서를 모을수록 징후가 구체적. 손맛은 탐험(맵 난이도, 오르기·잠수 등)에서.
- 최종 반전과 세계 간 복선은 이번 구현에서 제외.
- 그래픽은 마지막에 입힌다. 주인공·캐릭터·배경은 컨셉아트 시안을 여러 개 보여 주고 확인받은 뒤 작업. 전투 화면도 텍스트만이 아니라 플레이어·적 그래픽 연출이 필요.
- 모든 결정은 사용자에게 검증받고 진행한다.
